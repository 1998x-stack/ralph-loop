# V1.3 — Worktree candidate isolation, trusted replay, private integration branch

Status: implemented and CI-tested, **not an OS security sandbox**.

## Execution flow

1. Validate nonempty PRD, trusted verification manifest and a **clean Git repository**. Both PRD and manifest must be committed; do not run against dirty source trees.
2. Acquire exclusive `.ralph/run.lock` and persist the V3 run state, with a pinned source SHA, current integration SHA and run-owned ref `refs/heads/ralph/run-<uuid>`.
3. Create an ephemeral detached **candidate Worktree** from the current integration commit. Spawn the Coding Agent there with fresh context. It is given the assigned Story, not the test workspace path.
4. Scan all tracked/untracked candidate changes. Reject deletes, renames, symbolic links, nonregular files, executable mode changes, protected files, paths outside trusted `allowedPaths`, more than 80 changed files, or a patch larger than 2 MiB.
5. Stage approved files and compute a bounded binary Git patch and patch fingerprint. Create a **new review Worktree** from the pinned base SHA and apply exactly that patch with `git apply --check --index` / `git apply --index`.
6. Run independent verifier subprocesses against the review Worktree, using the **original trusted manifest**, not one supplied by the Agent. Ensure protected source/tests, PRD and manifest hashes, and Git candidate status remain unchanged across checks.
7. The deterministic Evaluator requires all applicable checks to pass. Store results, patch hash, base SHA, changed paths and verdict in the run's attempt evidence file.
8. If accepted, create a reviewed commit with Git hooks disabled and advance **only the run-owned Git ref** with a compare-and-swap update; update `.ralph/state.json`. A later Story is based on that accepted commit. Failed candidates are discarded.
9. Remove both Worktrees and temporary directories; cleanup problems cause fail-closed behavior.

## CLI

Requires Node.js 20+ and Git.

```bash
# From the target project root with committed PRD, CLAUDE.md and verification manifest
node /path/to/ralph-loop/ralph-node.js --verify ralph.verify.json --dry-run
node /path/to/ralph-loop/ralph-node.js --verify ralph.verify.json --max-iterations 20 --max-attempts 3
node /path/to/ralph-loop/ralph-node.js status
```

The CLI now selects the Worktree runner by default when `--verify` is supplied.
`--unsafe-inplace` explicitly opts into the older V1.2 process-only runner.
`--legacy-unverified` opts into the V1.1 unverified runner.
Neither escape hatch is recommended for unattended development.

## Manifest example

```json
{
  "version": 1,
  "allowedPaths": ["src/**", "app/**"],
  "protectedPaths": ["scripts/verification/**"],
  "checks": [
    {"id":"unit","command":"npm","args":["test"],"timeoutSeconds":180},
    {"id":"typecheck","command":"npm","args":["run","typecheck"],"timeoutSeconds":180}
  ]
}
```

This example is a **policy**, not a valid command set for every project. Use reviewed checks, scoped `storyIds` if appropriate, and adjust `allowedPaths` to the intended code. Generated test artifacts must be ignored by Git or written outside the review Worktree; changes to Git status during tests invalidate the evidence. `allowedPaths` supports exact files, a single-level `dir/*`, or recursive `dir/**` patterns, not a full glob engine.

## Reviewing accepted code

A run completes with `runRef` and `integrationHead`. It does **not** modify the checked-out main branch or push to a remote. Inspect the private run branch and its diff against your chosen base before any deliberate merge:

```bash
git branch --list 'ralph/run-*'
git log --oneline ralph/run-<run-uuid>
git diff main...ralph/run-<run-uuid>
```

No automatic merging, pull request creation, force push or cleanup of run refs is performed. A Story marked `passed` means only that its configured checks passed for the recorded patch, not that the whole software system is correct.

## Reliability and threat model

- **Supported:** accidental test rewrites, forbidden file edits, forged PRD completion, empty candidates, erroring tests, failed tests, duplicated task attempts, private integration branch preservation, and pause/resume with unchanged trusted source.
- **Not yet supported:** unclean crash recovery from `running` state, interrupted Git update-ref/state write reconciliation, automatic stale lock cleanup, deterministic cost limits, re-entrancy across hosts, a trusted evaluator identity, secure Git hooks under all user configurations, or reliable handling of arbitrary dependencies requiring network/services.
- **Not a security boundary:** Worktrees share the same Git object database and operating-system UID. An Agent with the same filesystem rights can potentially reach the source repo, gitdir, `.ralph` evidence and external paths. Test subprocesses run under the same identity, so malicious project code can affect the host. Protected hashing detects a limited class of changes; it does not prevent active attackers.
- **Before untrusted code:** add container/OS namespace isolation, read-only mounts for trusted inputs, separate writable volumes, a supervisor-held evidence store and explicit network/secret policies. Run only in trusted workspaces until then.
- **Existing V1.2 run state:** V1.3 fails closed rather than silently importing schema V2. Review and archive old state before starting a separate V1.3 run.
