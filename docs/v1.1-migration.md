# V1.1 Migration and Verification

The `feat/v1.1-reliability-core` branch introduces the first reliability-focused batch. **It is not a production-ready autonomous harness.**

## Requirements

- Node.js >= 20; Git
- A target project containing `prd.json` and `CLAUDE.md` at the project root
- A configured Claude Code CLI or Amp CLI for live execution

## Commands

```bash
npm test
npm run check
node src/core/prd-cli.js validate prd.json
node src/core/prd-cli.js summary prd.json
# From a target project, call these using an absolute path:
node /path/to/ralph-loop/ralph-node.js --dry-run
node /path/to/ralph-loop/ralph-node.js --max-iterations 20 --max-no-progress 3 --timeout-seconds 600
```

## Behavioral changes

1. An empty PRD is invalid; unlike old Bash behavior, it cannot finish successfully.
2. `blocked` stories are counted separately and never as passed.
3. Story dependencies must exist and form a DAG; highest-priority **ready** story is selected deterministically.
4. Failed child-process exit codes stop the run, even if the PRD was altered.
5. One iteration may not complete multiple stories; a run stops after configured no-progress attempts.
6. `--dry-run` prints task readiness without modifying PRD or falsely claiming completion.
7. `--cost-limit` fails explicitly; no billing metric is yet available.
8. The Bash CLI delegates to Node, requiring Node 20+.
9. Claude Code runs in noninteractive print mode with normal permissions. Configure explicit permissions beforehand.
10. The plugin Stop hook is informational, not an execution coordinator.

## Current gaps

- No independent evaluator or verified test evidence; `passes:true` is still a legacy trust boundary.
- No durable retry counter, checkpoint, or recovery after unclean interruption.
- No Worktree sandbox or container isolation.
- No reliable token-cost accounting.
- No real Claude/Amp SDK integration test in CI; only fake-agent integration tests.
- Prompt claims about automatic git commits and rollback are **not** enforced by core code.

## Testing

`npm test` runs state validation and fake-agent orchestration tests without API keys. GitHub Actions checks Node syntax, shell syntax, and the test suite. Live CLI smoke testing must be performed separately with appropriate permissions.
