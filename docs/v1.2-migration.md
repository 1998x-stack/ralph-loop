# V1.2 — Verified Execution and Evidence Gate

This release introduces a **separate, opt-in-to-manifest but fail-closed-by-default** verified runner. It uses a typed Run / Story / Attempt state machine, external test commands, deterministic evaluation, and persisted evidence.

## Start in a target Git repository

Create a trusted `ralph.verify.json` with `version:1` and at least one check for every story. Each check has `id`, executable `command`, string `args`, and optional `storyIds` and `timeoutSeconds`. Refer to `schemas/ralph.verify.example.json` for an example. Only put commands and check definitions from a trusted source in this file.

```bash
node /path/to/ralph-loop/ralph-node.js --verify ralph.verify.json --dry-run
node /path/to/ralph-loop/ralph-node.js --verify ralph.verify.json --max-iterations 20 --max-attempts 3
node /path/to/ralph-loop/ralph-node.js status
```

If `--verify` is omitted the CLI **refuses autonomous execution**. To use the previous unverified behavior explicitly, pass `--legacy-unverified` (not recommended).

## Authority and state

- `prd.json` is a **read-only specification** for the run; agent changes to it stop the run. The old `passes:true` field is not evidence and does not mark the story passed. Even previously passed legacy stories must be independently reverified on first V1.2 run.
- `.ralph/state.json` holds the typed run state, attempts, and story statuses. Writes are atomic. The `run.lock` file prevents accidental concurrent invocation. A stale lock is intentionally NOT auto-removed.
- `.ralph/artifacts/<attempt-id>.json` stores check output, pass/fail, the manifest fingerprint, and evaluator decisions. These are bound to the attempt ID.
- A story can become `passed` only from the deterministic evaluator following successful independent process checks.
- Test and configuration files under protected directories are fingerprinted. Changes by an agent block verification before any test is run.
- `paused` executions (iteration limit or no progress) may be restarted. Unclean shutdown recovery is deliberately fail-closed for this version and must be handled in V1.4.
- This version does not use an LLM Judge: the independent evaluator is a deterministic evidence gate. A judge will be optional later and cannot override failed checks.

## Security and limits

The CLI and test runner are independent **processes**, not isolated OS identities. A coding Agent with the same filesystem permissions could still modify arbitrary workspace files or `.ralph/` state. V1.3 must add Worktree/container isolation and move immutable evidence out of the Agent's writable namespace. Protected tests are a detection measure, not a tamper-proof sandbox. Test command scripts outside protected paths and commands' transitive dependencies are not automatically sealed. Check authors must review the full dependency chain.

The old `passes` field remains in the PRD for backwards compatibility, but V1.2 never edits it. PRD summaries from the old `prd-cli.js` show legacy flags, not verified state. Use `ralph-node.js status` for authoritative verified execution state. No automatic PRD migration, merging, model cost budget, or Worktree isolation is implemented yet.

## Testing

```bash
npm test
npm run check
```

The suite uses Fake Agents and real test subprocesses, including failure evidence, `passes:true` spoofing, dependency execution, retry blocking, protected-file changes, pause/resume, and locking. Live Claude CLI runs remain environment-dependent and are not verified by CI.
